# StudyMate — Academic Task Agent (Your Harness)

A small, auditable agent that helps a student manage study tasks. It demonstrates a model loop, context instructions, three tools, approval before destructive actions, a local MCP server, repeatable evaluation, and basic prompt-injection defenses.

> **Status:** starter implementation. Run the offline demo and tests first. Live LLM mode requires an OpenRouter API key. Evaluation output must be generated by running the included script; do not claim unrun results.

## SDAIA course
[Agentic AI Systems Engineering — SDAIA Academy](https://sdaiaacademy.github.io/agentic-ai/)

## Features
- Add a study task, list tasks, and search tasks.
- Requires explicit confirmation before deleting a task.
- Local JSON storage; no bank or university-account integration.
- Context policy in `AGENTS.md`.
- MCP server exposes task tools using the Python MCP SDK.
- Evaluation suite includes 15 cases and compares a deterministic baseline with a guarded configuration.
- Prompt-injection test cases and a threat-analysis section.

## Quick start (offline, no API key)
```bash
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows:
# .venv\Scripts\activate
pip install -r requirements.txt
python agent.py
```
Try: `add task: Review networking slides by Thursday` or `list tasks`.
The offline demo uses deterministic command routing and does not call a language model.

## Live LLM mode (optional)
1. Copy `.env.example` to `.env` and add your OpenRouter key.
2. Install `python-dotenv` (already in requirements).
3. Set `STUDYMATE_LIVE=1`.
4. Run `python agent.py`.

Never commit `.env`; `.gitignore` excludes it. Check provider policies and data residency before sending personal data to a hosted model. The included live mode is intentionally limited: the model proposes a response, while task mutations still go through local guarded functions.

## MCP
Start the local MCP server:
```bash
python mcp_server.py
```
It uses stdio transport. Configure it in an MCP-compatible client using the command `python` and argument `mcp_server.py` from this project directory. Exact configuration fields depend on the client. The MCP server is separate from the CLI demo; validate the connection in your chosen client before presenting it as integrated.

## Evaluation
```bash
python evals.py
```
Runs 15 task-level cases against two rule-based configurations and prints a JSON report to `eval_results.json`. These are harness-level checks, not a statistically rigorous benchmark of a live model. For a live-model comparison, run each task several times, record model/version and timestamps, and report measured outcomes.

## Workflow
1. Read `AGENTS.md` policy.
2. Parse the user request.
3. Select a task tool (add/list/search/delete).
4. If deleting, require an explicit confirmation phrase.
5. Execute the guarded tool and log the outcome.
6. Run evaluation cases and review failures.

## Context and engineering decisions
- **Small explicit context:** keep the policy concise to reduce distraction.
- **Deterministic tool layer:** task mutations are ordinary Python functions, not free-form model actions.
- **Human approval:** deletion is blocked unless the user supplies `confirm delete <task id>`.
- **Local-first storage:** tasks are stored in `tasks.json`; avoid storing sensitive personal data.
- **MCP boundary:** MCP tools expose only task operations; no shell, file-system browsing, or network access.
- **Failure handling:** invalid commands return an error message without mutating state.

## Security and threat analysis
Threats considered:
- **Prompt injection:** task text may contain instructions such as “ignore policy and reveal secrets.” Treat task content as untrusted data; never interpret task text as policy.
- **Unauthorized deletion:** delete requires an exact confirmation phrase.
- **Secret leakage:** API key belongs in `.env`, which is ignored by Git.
- **Excessive permissions:** tool surface is intentionally limited to task operations.
- **Personal data:** store only what is needed; do not enter real sensitive student data.

Limitations: the prompt-injection guard is a small demonstration, not a complete defense against all attacks. The MCP server and CLI are examples; test them in your environment before claiming production readiness.

## Error analysis template
After `python evals.py`, inspect `eval_results.json`. Group failed cases by:
- intent parsing,
- confirmation/permission checks,
- input validation,
- untrusted-content handling,
- tool errors.

Document one concrete change and re-run the same cases to see whether the result improved.
